# Embedded workbench

Command–Shift–I opens a local VS Code-based code-server workbench in a Webby tab. It remains compatible with Webby's split layouts. Open Project and New Project are native glass controls; explorer, editor, integrated terminal, Problems, extensions, and Run and Debug come from the workbench.

Run `python3 install_ide_runtime.py` on Apple Silicon macOS to install the pinned, checksum-verified runtime and Java extensions. This installer keeps its own Node runtime and does not modify Homebrew or existing browser profiles. The runtime and settings live under `~/Library/Application Support/Webby IDE/`; browser website cookies are not used. Project files remain in the folders you choose.

Java support includes Red Hat's language server, Java Debugger, and Project Manager for Java, using Open VSX. This is a VS Code-based distribution, not Microsoft's desktop application: Microsoft-only extensions or services are not guaranteed compatible. A JDK is required for compiling and running projects. Project trust remains enabled.

The local server binds only to 127.0.0.1 on a private port that is reused when available. Each Webby process generates an in-memory password; IDE tabs share their own persistent WebKit store on macOS 14+, isolated from website profiles (nonpersistent on macOS 13 and in tests). Restored IDE tabs start the runtime only when shown. All workbench tabs share the server and extension directory. The server stops ten seconds after the last IDE tab closes, or when Webby quits. Workbench recovery data persists so unsaved documents can be recovered; auto-save is off by default. Save before closing. Closing a workspace asks for confirmation.

Workbench panes use translucent theme colors over Webby's native backdrop. Scrolling and caret movement use workbench animation support; native controls and split transitions use Webby's Motion helpers. Reduced motion follows macOS. This is heavier than the old text editor, so no claim of zero resource overhead is made.

Webby's Command–Shift–F remains reserved for Fuse. For workbench-wide search use its Search view or Command Palette. Command–F and Command–S are routed into the IDE for Find and Save. See WEBBY-SHORTCUTS.md for the complete browser shortcut list.

Efficiency defaults exclude `.webby-build`, Gradle caches, and dependency caches from unnecessary watching/importing/searching, turn off the minimap unless explicitly enabled, skip parent-repository discovery, and disable terminal persistence after a workspace closes. Existing settings win, including JSONC comments and explicit exclusions. Before adding missing defaults, Webby keeps a `settings.json.before-webby-energy` backup. Running terminals remain connected while switching tabs.

Startup settings preparation and migration run on a utility worker rather than the UI thread. Runtime output is drained and parsed off the UI thread; only the initial ready signal is delivered to the UI. The IDE uses one native glass layer. Java uses one full-feature language server and retains its normal heap headroom and processor availability: experimental hard limits were rejected after they slowed the fixture workflow. No running debugger or command is frozen to save power.

`Tests/sample_ide_resources.py` measures backend descendants around an isolated native workbench fixture, including real Java diagnostics and breakpoint debugging. Its resident-memory sums exclude WebKit rendering/XPC processes and are not whole-app or battery-life measurements. The fixture checks that backend processes exit after cleanup; results live under `work/ide-*-resources.json` outside the source tree.

The IDE widget (Add Widget → IDE) uses the Folded Portal vector mark and a shared recent-folder list. Wide cards show the project sidebar beside the mark; tall cards stack them; short cards become a folder strip; tiny cards expose the complete list through the mark. Very narrow cards use folder icons with path tooltips. All Projects exposes folders that do not fit. Right-click a folder to remove its shortcut without deleting files. Missing folders are checked on activation, off the UI thread. Existing workspaces are reused within the current profile/Fuse; stale clicks are cancelled after a profile change or a newer open action. The widget imports the older native project list and the workbench's last saved folder, then records future folder openings. It does not scan the disk while resizing or start the IDE backend merely to show the list.
